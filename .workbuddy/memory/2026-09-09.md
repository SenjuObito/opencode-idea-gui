## 关键构建坑：tsc 因依赖版本漂移失败

- 仓库**没有 pnpm-lock.yaml**(只有 npm 的 package-lock.json)，pnpm 按 semver 实时解析，
  依赖会漂到新版。`marked-katex-extension` 升到 5.1.12 后开始发布 `types: ./src/index.ts`，
  tsc 解析 import 到其**源码**并因 `noUnusedLocals` 报 TS6133，挡住 `pnpm/npm run build`
  (build.gradle 中 `compileJava dependsOn buildWebview`)。
- 修复：`webview/tsconfig.json` 加 `baseUrl:"."` + `paths` 把 `marked-katex-extension` 指回
  项目自带 shim `src/types/marked-katex-extension.d.ts`。改后 `tsc` 0 错误，`npm run build` 全绿。

## 第二轮：webview 侧丢失事件（修复后仍卡）

- 10:24 新日志显示修复已生效：`frontend_ready` 时 `checkAndPush invoked (alive=true,
  lastServeReady=true)` 直接重申 `pushStatus {"alive":true,"serveReady":true}` 并于
  `10:24:24.485` `executed window.updateDaemonStatus`。宿主推送链路已正确。
- 但截图仍显示顶部 toast「Checking daemon status...」和底部横条「正在启动 OpenCode 服务，请稍后」，
  说明 webview 的 `daemonStatusLoaded` 未翻为 true。
- 真正根因：`updateDaemonStatus` 在 `main.tsx` 里只 `dispatchEvent(new CustomEvent(...))`，
  而 `useUsageTracking` 的 listener 在 React mount 后的 `useEffect` 才挂上。宿主在 `frontend_ready`
  之前/同时推送的状态事件，极可能在 listener 挂上前就丢了（CustomEvent 不排队）。
- 对比：`setSessionId`、`updateSendShortcut`、`onModeReceived` 等早期推送在 `main.tsx` 都有
  `window.__pending*` 兜底 + `drainPendingSettings` 消费；`updateDaemonStatus` 是唯一没有兜底的状态。
- **修复**：
  - `main.tsx` 的 `window.updateDaemonStatus` 先存 `window.__pendingDaemonStatus = json`，再 dispatch。
  - `useUsageTracking.ts` 的 `useEffect` 在挂 listener 后立即 drain `__pendingDaemonStatus`，
    解析并 setDaemonAlive/setDaemonStatusLoaded，避免早到事件丢失。
  - `global.d.ts` 声明 `__pendingDaemonStatus?: string`。
- 编译验证：`tsc` 0 错误；`./gradlew classes -PskipWebview=true` BUILD SUCCESSFUL，
  资源文件 `src/main/resources/html/opencode-chat.html` 已更新。

## 根因已定位并修复：checkAndPush 回退 serveReady

- **现象**：启动卡「正在启动 OpenCode Serve服务，请稍后」、发不出消息。
- **证据**(opencode-plugin.log @ 10:06)：`10:06:28.558` 首次 `serveReady:true` 已
  `executed`(本该关 loading)；`10:06:31.957` `frontend_ready`→`checkAndPush()` 无条件先推
  `serveReady:false`(L108) 并于 `10:06:31.969` `executed`，把正确状态覆盖回 false；`10:06:31.972`
  preconnect 再推 `serveReady:true` 的修正依赖脆弱链路(重新 preconnect 成功 + 恰好送达)。
- **根因**：`DaemonStatusHandler.checkAndPush()` 在 daemon 早已 ready 时仍先推 false 占位，
  且 `preconnectInFlight=true` 时 `preconnectAndPush` 直接 return 不发任何推送(无修正)。
- **修复**(`DaemonStatusHandler.java`)：加 `lastAlive/lastServeReady` 状态记忆；
  `checkAndPush` 中若 `alive && lastServeReady` → 直接重申 `pushStatus(true,true)` 不再回退；
  若 `preconnectInFlight` → 直接 return(把推送权交给在飞的 preconnect)；否则才走原占位+preconnect。
  `pushStatus` 同步写入记忆；`onDaemonDied` 自然把 `lastServeReady` 置 false。
- `callJavaScript` 的 "call"/"executed" 日志是 **throttled(2000ms)** 的(L2114/2153)，仅压日志、
  L2152 `executeJavaScript` 不受限流影响——日志里看不到某次推送不代表没执行。
- 编译验证：`./gradlew compileJava -PskipWebview=true` 与 `./gradlew buildWebview` 均 BUILD SUCCESSFUL。

## 第三轮：上传 gradlew 文件后报错 `File part media type 'application/octet-stream' functionality not supported.`

- **现象**：用户点击上传文件（截图中为 `gradlew`），发送消息后报错；同目录 `opencode-vscode-plugin` 同样问题。
- **根因**：旧版 `useAttachmentHandlers.ts` 对无法识别的文件 fallback 为 `mediaType: file.type || 'application/octet-stream'`。
  浏览器对无扩展名脚本（如 `gradlew`）返回空 `file.type`，于是 webview 把 `application/octet-stream` 发给宿主；
  opencode 在 Copilot-compatible provider 路径上会把非图片 file part 转成 OpenAI 消息，遇到 `application/octet-stream`
  即抛 `UnsupportedFunctionalityError`。
- **修复范围**：
  - **IDEA webview**：`webview/src/components/ChatInputBox/hooks/useAttachmentHandlers.ts` 已改为
    `rawType && rawType !== 'application/octet-stream' ? rawType : ''`，让后端按文件名/扩展名推断 MIME；
    并重新 `npm run build` 生成 `src/main/resources/html/opencode-chat.html`。
  - **VSCode webview**：同步修改 `webview/src/components/ChatInputBox/hooks/useAttachmentHandlers.ts` 并重新 build，
    产物同步到 `dist/webview/index.html`。
  - **共享 ai-bridge**：`ai-bridge/utils/cli-image-input.js` 的 `resolveAttachmentMimeType` 增加最终 guard：
    即使上游仍传来 `application/octet-stream`，也强制 fallback 到 `text/plain`（配合扩展名推断），
    避免 octet-stream 进入 opencode server。同步到 `opencode-vscode-plugin/ai-bridge/utils/cli-image-input.js`。
  - **IDEA 宿主兜底**：`SessionHandler.java` 中附件 mediaType 缺失时默认从 `"application/octet-stream"` 改为 `""`
    让 ai-bridge 走推断路径。
  - **VSCode 宿主恢复**：`src/host/session/SdkMessageConverter.ts` 的显示 fallback 从 `application/octet-stream` 改为 `""`
    （非发送路径，仅为显示一致）。
- **验证**：`node --test ai-bridge/utils/file-parts.test.js` 在两个仓库均 10 pass；
  IDEA `./gradlew compileJava -PskipWebview=true` BUILD SUCCESSFUL；
  VSCode `node esbuild.js --production` 成功，`dist/extension.js` 不再含 `application/octet-stream` 硬编码。
- **用户操作**：IDEA 侧 `./gradlew runIde -PskipWebview=true`（webview 已打好）；VSCode 侧 reload window 或重装本地扩展。
