# 验证：opencode SDK 是否支持 file part 传输文件

## 目的

实测回答：`@opencode-ai/sdk/v2`（插件 ai-bridge 同款客户端）发送 `FilePartInput { type:'file', mime, filename, url }` 是否被服务端接受、三种 URL 形态落库后的实际 parts 结构是什么。

## 脚本

保存到 `.zcode/skills/opencode-api-verify/scripts/test-file-part.mjs`（该技能就是做 API 验证用的，脚本可复用）：

const client = createOpencodeClient({ baseUrl: BASE_URL });

// 0. 健康检查

（运行时会打印每个落库 part 的完整关键字段，足以判断：file part 是否原样保留、服务端是否把文件内容展开成 synthetic text parts、@token 文本是否原样保留。）

## 关键检查点

1. `prompt_async` 是否 200/204（400 = schema 拒绝 → SDK 不支持该形态）
2. 落库 user message 的 parts 里：
   - 3 个 file part 是否原样保留（mime/filename/url）
   - 是否出现 `synthetic: true` 的 text parts（服务端 Read 展开："Called the Read tool…" + 文件内容）
   - 图片 file part 的 url 是否被服务端改写（image.normalize）
   - `@notes.txt` 文本是否原样在 text part 里

## 清理

- 删除测试会话（DELETE /session/{id}）
- 删除临时目录

运行结果 + 每种 URL 形态的落库结论，作为后续附件/历史显示方案的证据。
