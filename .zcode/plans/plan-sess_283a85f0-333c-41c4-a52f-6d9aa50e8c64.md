# 技术方案：将 jetbrains-cc-gui 改造为 opencode 专属 JetBrains 插件

## 一、目标与现状

**现状**：jetbrains-cc-gui（"CC GUI"，v0.5.4）是 Claude/Codex 双引擎为主、外加 Grok/Kimi/OpenCode/Pi/OMP/DeepSeek 的多引擎 IntelliJ 插件。三层架构：JCEF+React webview → Java 插件宿主 → Node.js ai-bridge 守护进程。其中 OpenCode 目前走 `MarkerCliBridge`（每条消息 spawn 一次 `node channel-manager.js opencode ...`），无会话持久化复用。

**参考**：`I:\source\repos\opencode-vscode-plugin`（opencode-buddy）就是本项目的 TypeScript 移植版，且已完成"去多引擎 + opencode 化"：常驻 daemon + `opencode serve --port 4096` + `@opencode-ai/sdk v1.18.15 /v2 入口` + SSE 事件流。其目录（`src/host/{router,handlers,session,provider,tabs}`、`ai-bridge/services/opencode/`、`webview/`）与本项目 Java 侧目录同名同职责，可逐文件映射。

**目标**：在原项目内改造为 opencode 专属插件，全量重命名品牌标识，功能集对齐 VSCode 版（保留 JetBrains 特色：多标签、脱离窗口、主题/字体同步、终端集成）。

**改造后架构**：
```
webview (React, JCEF)  ⇄  Java 插件宿主 (JBCefJSQuery + MessageDispatcher)
                       ⇄  ai-bridge daemon (NDJSON over stdio, 常驻)
                       ⇄  opencode serve --port 4096 (HTTP, @opencode-ai/sdk v2)
                       ⇄  event.subscribe SSE (按 directory 作用域)
```
NDJSON 协议与 marker 协议（`[MESSAGE_START]/[STREAM_START]/[CONTENT_DELTA]/[THINKING_DELTA]/[MESSAGE]/[PERMISSION_REQUEST]/[QUESTION_REQUEST]/[TODO_UPDATED]/[REVERT_STATE]/[USAGE]/[MESSAGE_END]/[STREAM_END]/[SEND_ERROR]`）直接照搬 VSCode 版，Java `DaemonBridge` 已实现同款协议（心跳 15s/超时 45s/活跃请求 180s/崩溃重启≤3 次），复用度高。

## 二、实施阶段

### Phase 0：基线（0.5 天）
1. `git init` 并提交当前状态作为基线（当前目录不是 git 仓库）。
2. 跑通 `./gradlew buildPlugin`、webview/ai-bridge 的现有测试，记录基线。

### Phase 1：品牌与全量重命名（1 天）
- 插件 ID：`com.github.claudecodegui` → `com.senjuobito.opencode-buddy`（与 VSCode 版 publisher 对齐）；插件名 → "OpenCode Buddy"。
- Java 包名：`com.github.claudecodegui` → `com.opencodebuddy`（338 个文件，用 IDE/脚本批量 refactor + 正则替换 import）。
- 资源层：`plugin.xml`（toolWindow id `CCG` → `OpenCode`、notificationGroup、action 文案）、i18n bundle（`messages/`）、图标（`icons/` 中 Claude logo 换 opencode logo）、`gradle.properties`/`build.gradle` 产物名、README/CHANGELOG。
- 配置目录：`ConfigPathManager` 的 `~/.codemoss/` → `~/.opencodebuddy/`（不做数据迁移，全新目录）。
- 临时目录 `claude-agent-tmp` → `opencode-bridge-tmp`；系统属性 `claude.bridge.path` → `opencode.bridge.path`。

### Phase 2：拆除多引擎与 Claude 专属功能（2 天）
**Java 侧删除**：
- `provider/{claude,codex,grok,kimi,omp,pi,dsh}/`（保留改造 `provider/opencode/` 与 `provider/common/DaemonBridge.java`）
- `handler/provider/*`、`session/ClaudeMessageHandler/CodexMessageHandler/GrokMessageHandler`、`SessionProviderRouter` 简化为单路由
- `provider/common/MarkerCliBridge.java`（opencode 不再走每消息 spawn）
- `settings/ClaudeSettingsManager`（~/.claude/settings.json 同步）、`ProviderManager`/`CodexProviderManager`（cc-switch 多供应商预设）
- `handler/provider/claude/ClaudePlanUsageHandler` + `ClaudePlanUsageService`、`provider/pricing/*`、`ModelPricing`/`CustomModelPricingHandler`
- `handler/GenerateCommitMessageAction` + `service/commit/*`（VSCode 版无此功能）
- `read-cc-switch-db.js`、`mcp/` 中 Copilot 之外的 Claude 专属导入逻辑、`pet/`（Claude 吉祥物）
- `dependency/DependencyManager`+`SdkDefinition`（SDK 按需安装机制不再需要，opencode SDK 随 ai-bridge 打包）
- `permission/PermissionRequestWatcher`（跨进程文件监听，Claude hook 方案专用）
- 可选模块 `java/python-features.xml` 中仅为 Claude 上下文服务的部分

**ai-bridge 删除**：`services/{claude,codex,dsh,grok,kimi,omp,pi}/`、`channels/` 中对应 channel、`config/api-config.js`（~/.claude env 注入）。

**webview 删除**：`claudeModelMapping.ts`、`useClaudePlanUsage.ts`、多引擎 `ProviderDialog`、settings 中 provider/cc-switch 分区。

### Phase 3：OpenCode 桥接升级（核心，3 天）
**ai-bridge（从 VSCode 版逐文件移植，Node 代码可直接复用）**：
- `services/opencode/opencode-serve-manager.js` — 二进制解析（`OPENCODE_BIN/OPENCODE_PATH/OPENCODE_CLI_PATH` env → PATH → `~/.opencode/bin`、`~/.local/bin` 等；Windows `.cmd` shim 用 `shell:true`）→ 先探测 `localhost:4096`（1.5s）复用已有实例，否则 spawn `serve --port 4096`，300ms 轮询就绪，15s 超时；Unix SIGTERM/Windows taskkill 清理。
- `services/opencode/opencode-sdk-client.js` — `@opencode-ai/sdk`（`ai-bridge/package.json` 新增 `^1.18.15`，**随插件打包**）封装全部 API：`session.create/list/get/delete`、`promptAsync`、`session.shell`、`session.command`（斜杠命令，model 传 `"provider/model"` 字符串）、`session.abort/summarize/share/unshare/revert/unrevert/fork/messages`、`event.subscribe`(SSE)、`config.providers`、`app.agents`、`command.list`、`permission.reply`、`question.reply/reject`、`v2.fs.find`、`mcp.status`。
- `services/opencode/opencode-daemon-service.js` — 每个 directory 一条 SSE 订阅，按 sessionID 路由，处理 `message.part.updated/delta`、`session.idle/error/compacted`、`permission.asked`、`question.asked`、`todo.updated` 等全部事件 → marker 输出。
- `utils/{cli-path,marker-protocol,cli-spawn,cli-image-input,path-utils}.js`、`event-normalize.js`、`models-service.js` 直接拷贝。
- `daemon.js` 方法路由收敛为：`opencode.send/shell/preconnect/getContextUsage/listModels/replyPermission/replyQuestion/rejectQuestion/abort/heartbeat/status/shutdown`（AsyncLocalStorage 请求隔离、stdout 拦截打 `{id,line}` 包、turn 串行队列、ppid 防孤儿——逻辑照搬 VSCode 版）。

**Java 侧**：
- `provider/common/DaemonBridge.java` 保留（协议同款），`provider/opencode/OpenCodeSDKBridge.java` 重写为 daemon 调用方：`opencode.send`（promptAsync）、流式回调对接 `MarkerParser`。
- `session/` 层：`ClaudeSession` 改名 `OpenCodeSession`，回调集收敛为 VSCode 版 `SessionCallback` 接口（onContentDelta/onThinkingDelta/onStreamStart/End/onUsageUpdate/onSessionIdReceived/onPermissionRequested/onPermissionClosed/onTodoUpdated/onRevertStateUpdate）；保留 `MessageMerger`（按 content block id 原地替换工具块）、`StreamDeltaThrottler`/`StreamMessageCoalescer`/`ReplayDeduplicator`。
- **历史改造**：删除 sqlite-jdbc 直读 opencode SQLite 库，改走 `session.messages` API（`{info, parts}`，part 类型 text/reasoning/tool）。
- 会话启动预热：项目打开后（`BridgePreloader`）即 `opencode.preconnect`（spawn serve + SSE 订阅 + 解析/创建会话）+ 模型目录缓存。

### Phase 4：Handler、权限与 webview 适配（2 天）
- **权限**：opencode 的 `permission.asked` 经 SSE→marker→`PermissionManager`，IDE 内弹 `PermissionDialog`（保留现有 UI），回复映射 `permission.reply {requestID, reply: 'once'|'always'|'reject'}`；`question.asked` 同理。删除 Claude hook 式 `ToolInterceptor`。permissionMode 选择器映射为 opencode agent（build/plan）选择。
- **Handler 收敛**：保留 `Session/History/Diff/File/Tab/Context/McpServer/McpMarketplace/Skill/Settings/FontConfig/UndoFile/TokenTracker`（均与 VSCode 版 handlers 一一对应）；`RewindHandler` 改接 `session.revert/unrevert/fork`；`McpServerHandler` 改接 `mcp.status`；`SkillHandler` 改接 `command.list`（frontmatter 解析保留）。
- **webview**：以 VSCode 版 `webview/src` 为准逐组件核对（它本就是 cc-gui 前端的移植，组件基本同构），主要差异点：模型选择器数据源改为 `config.providers` 返回的 `{providerID, modelID}`、agent(mode)/variant(推理力度) 选择器、token 用量环接 `[USAGE]`、@file 搜索接 `v2.fs.find`。桥接层保留 JCEF 版 `bridge.ts`（不换成 vscode postMessage）。
- **设置**：`opencode.tuiPath` 等价物 → 复用现有 `ClaudeCliPathHandler` 改名 `OpenCodeCliPathHandler`；新增 `OPENCODE_PORT` 可配置项与 `verboseDiagnostics` 日志开关（对齐 VSCode 版唯一配置项）。

### Phase 5：构建与 CI（1 天）
- `build.gradle`：`packageAiBridge` 的排除清单从"排除 @anthropic-ai/@openai node_modules"改为**包含** `@opencode-ai` node_modules（SDK 随包分发，~几 MB）；webview 构建不变；产物名/描述/变更日志更新。
- `pluginVerifier` 目标不变（IC 2024.3.1 起，sinceBuild=233）；CI workflow（build.yml/tests.yml）与 Playwright/Vitest 改名适配。
- 移除不再需要的依赖：sqlite-jdbc、tomlj/snakeyaml（若仅 Claude settings 用）、JLayer 视音效功能去留。

### Phase 6：测试与验收（1.5 天）
- ai-bridge：marker 协议、sdk-client（mock SDK）、serve-manager（端口复用/Windows shim）单测。
- Java：DaemonBridge NDJSON 编解码、MarkerParser、MessageMerger、会话路由单测。
- `runIde` 手动验收清单：serve 自动拉起与复用、流式输出/思考增量、权限/问题审批、@file、`/bash`、历史加载、revert/fork、compact、MCP 状态、多标签与脱离窗口、主题/字体同步、Windows 下 `.cmd` shim。

## 四、风险与对策
1. **SDK v2 扁平参数随版本漂移**：锁定 `^1.18.15`，sdk-client 单测断言请求体形状（如 summarize 必须显式 `{providerID, modelID}`）。
2. **端口 4096 冲突/复用语义**：沿用"先探测后复用"策略 + `OPENCODE_PORT` 配置项；文档说明多 IDE 实例共享同一 serve。
3. **Windows `.cmd` shim**：保留 VSCode 版 `shell:true` spawn 处理与 `where.exe` 探测路径。
4. **大范围重命名**（338 文件）：先重命名、后删功能、最后接新链路，每阶段独立可编译提交。
5. **SSE 按 directory 作用域**：多项目窗口各自 directory 订阅，daemon 需维护 directory→subscription 映射（照搬 VSCode 版实现）。
